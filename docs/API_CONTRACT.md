# API Contract

## Game Result API

### POST /api/game-results

Submit a cognitive game result for the authenticated patient.

- **Authentication:** Required (JWT Bearer token).
- **Authorization:** Authenticated user must have role `PATIENT`.
- **Ownership:** The result is always attached to the authenticated user extracted from the JWT/SecurityContext. The client cannot supply `patientId` or `userId` to attribute the result to a different account; any such fields in the request body are ignored.

**Request body**

```json
{
  "gameType": "memory",
  "score": 8,
  "accuracy": 0.8,
  "reactionTime": 1200,
  "mistakes": 2,
  "difficulty": 1
}
```

| Field | Type | Notes |
|---|---|---|
| `gameType` | string | Required, non-blank. `memory` is the initial supported value; new game types can be added without changing the contract. |
| `score` | integer | Required, >= 0. |
| `accuracy` | number | Required, 0.0–1.0. |
| `reactionTime` | integer | Required, >= 0, milliseconds. |
| `mistakes` | integer | Required, >= 0. |
| `difficulty` | integer | Required, >= 0. |

**Response (201 Created)**

```json
{
  "id": 1,
  "gameType": "memory",
  "score": 8,
  "accuracy": 0.8,
  "reactionTime": 1200,
  "mistakes": 2,
  "difficulty": 1,
  "patientId": "PT-000001",
  "createdAt": "2026-09-06T12:30:00"
}
```

`createdAt` is generated by the backend; it is never accepted from the client.

**Status codes**

| Code | Meaning |
|---|---|
| 201 | Result saved. |
| 400 | Validation failure (e.g. `gameType` blank, `accuracy` outside 0–1, negative `score`/`reactionTime`/`mistakes`/`difficulty`). |
| 401 | Missing or invalid JWT. |
| 403 | Authenticated user is not a `PATIENT`. |

---

### GET /api/game-results/patient/{patientId}

Retrieve saved game results for a patient, newest first.

- **Authentication:** Required (JWT Bearer token).
- **Authorization:**
  - A `PATIENT` may only request their own `patientId` (matched against the authenticated user's `patientId`).
  - `CAREGIVER` and `HEALTH_WORKER` access is not implemented in this endpoint yet; no caregiver-patient relationship model exists. These roles currently receive `403` for any `patientId`. The endpoint is structured so authorized caregiver/health-worker access can be added later (see Issue #4 / #9) without changing this contract.

**Response (200 OK)**

```json
[
  {
    "id": 3,
    "gameType": "memory",
    "score": 9,
    "accuracy": 0.9,
    "reactionTime": 1000,
    "mistakes": 1,
    "difficulty": 2,
    "patientId": "PT-000001",
    "createdAt": "2026-09-06T14:00:00"
  },
  {
    "id": 1,
    "gameType": "memory",
    "score": 8,
    "accuracy": 0.8,
    "reactionTime": 1200,
    "mistakes": 2,
    "difficulty": 1,
    "patientId": "PT-000001",
    "createdAt": "2026-09-06T12:30:00"
  }
]
```

Results are ordered by `createdAt` descending (newest first).

**Status codes**

| Code | Meaning |
|---|---|
| 200 | Results returned (possibly empty array). |
| 401 | Missing or invalid JWT. |
| 403 | Authenticated user requested a `patientId` that is not their own. |
| 404 | Authenticated user record could not be resolved. |
